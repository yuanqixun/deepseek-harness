# 桌面企业登录准入

## Purpose

让启用企业认证的 DSH 发行版只在客户端拥有有效企业登录态后开放工作区和业务访问，并让未启用该插件的普通发行版继续保留原有使用方式，不把登录认证误作 TokenHub 业务授权。

## ADDED Requirements

### Requirement: 企业登录独立于模型凭据

要求企业认证的发行版 SHALL 在开放工作区和业务操作前检查有效登录态。DeepSeek 账号、API Key 和跳过欢迎页 SHALL NOT 替代企业登录；登录成功 SHALL NOT 自动提供模型凭据。首期 SHALL 不额外要求 TokenHub 授权。

#### Scenario: 已有模型凭据但没有企业登录

- **WHEN** 用户已有 API Key 或 DeepSeek 账号并尝试进入工作区，或触发跳过入口
- **THEN** 企业发行版仍要求完成企业登录，不开放业务操作

#### Scenario: 企业登录完成但没有模型凭据

- **WHEN** 用户完成企业登录而尚未配置模型凭据
- **THEN** 用户可进入模型配置流程，系统不将应用登录令牌当作模型密钥，不显示 TokenHub 授权已通过

### Requirement: Host 侧业务准入

系统 SHALL 在 Host 执行登录准入，覆盖业务 RPC、文件访问及流连接；未登录时仅允许必要的登录、启动、诊断和修复操作。前端页面隐藏或遮罩 SHALL NOT 作为唯一保护。

#### Scenario: 绕过界面直接请求

- **WHEN** 未登录调用方直接发起业务 RPC、文件读取或业务流连接
- **THEN** Host 拒绝操作，不返回业务数据，不因界面是否显示而改变结果

#### Scenario: 未登录时发起认证

- **WHEN** 未登录用户发起登录、查询自己的尝试或取消尝试
- **THEN** 必要认证操作可用，业务访问仍被拒绝

### Requirement: 登录失效后收回访问

系统 SHALL 在确认登录失效或完成本地退出后拒绝新的业务操作，包括经既有连接提交的操作；不得依赖重新建立连接才检查登录状态。运行中任务的终止或收尾规则须在设计中单独确定，不得将“拒绝新操作”描述成“全部任务已停止”。

#### Scenario: 已建立连接后的退出

- **WHEN** 用户退出后，旧连接尝试继续提交业务操作
- **THEN** 新操作被拒绝，连接存在本身不赋予继续访问权限

### Requirement: 必需认证组件失效时拒绝访问

要求企业认证的发行版 SHALL 在插件缺失、配置错误、加载失败或恢复模式禁用插件时拒绝业务访问，并保留必要修复能力，不得降级为普通免登录模式。

#### Scenario: 恢复模式禁用插件

- **WHEN** Desktop 恢复流程禁用了企业认证插件
- **THEN** 企业版可提示并修复加载问题，但不能进入可操作业务的免登录工作区

### Requirement: 普通发行版行为保持

未启用企业认证的发行版 SHALL 保留原有登录、模型配置和工作区流程，不请求企业登录服务，不要求企业配置或密钥。

#### Scenario: 不启用插件的运行

- **WHEN** 开发者或用户启动未装配企业认证的 DSH
- **THEN** 原有入口可正常使用，不新增 CAS 登录要求或企业认证网络请求
