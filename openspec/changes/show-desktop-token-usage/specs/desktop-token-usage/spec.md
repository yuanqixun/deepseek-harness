## ADDED Requirements

### Requirement: 登录用户查看本人 Key 与用量

Desktop SHALL 将登录后的现有账户菜单入口命名为“用量统计”，通过该入口打开“Token 用量”弹窗，展示登录用户名、当前 Key 掩码和现有模型 Key 状态，以及今日、本周、本月总 token。菜单入口 SHALL NOT 显示 Key 状态；弹窗 SHALL 保留 Key 状态和现有重试操作，且 SHALL NOT 展示完整 Key、额度或输入输出明细。

#### Scenario: 账户菜单入口

- **WHEN** 用户登录后打开账户菜单
- **THEN** 用量入口显示“用量统计”，而不是模型 Key 状态
- **AND** 用户可通过该入口查看 Key 状态和用量

#### Scenario: 查询成功

- **WHEN** 登录用户打开弹窗且当前 Key 可查询
- **THEN** 界面显示本人掩码和三个周期各自的总 token，以及最近一次整体刷新的日期和时间
- **AND** 周期名称为“今日”“本周”“本月”，数字后不显示各自时间，界面不标注时区

#### Scenario: Key 无法查询

- **WHEN** 当前用户没有可查询的 Key 或服务不可用
- **THEN** 界面显示相应状态，不将不可用结果显示为零

### Requirement: 本人只读访问

aicode SHALL 提供登录即可访问的 Desktop 本人 Key 状态和用量接口，从认证上下文确定用户，拒绝未认证访问，不接受调用方指定的目标用户或 Key。现有管理及本人管理页面接口的权限 SHALL 保持不变。

#### Scenario: 查询本人

- **WHEN** 已登录用户没有管理页面查询权限而调用 Desktop 本人接口
- **THEN** 服务仅返回该用户当前 Key 的脱敏状态或用量

#### Scenario: 无效身份或目标覆盖

- **WHEN** 请求身份无效，或尝试指定其他用户或 Key
- **THEN** 服务拒绝未认证请求，且不得返回其他用户的数据

### Requirement: 自然周期和查询状态

服务 SHALL 使用 Asia/Shanghai 的自然日、周和月起点至每次查询时刻，返回 TokenHub 记录的当前 Key 总量。界面 SHALL 在打开和整体刷新时查询各周期，允许失败周期单独重试，保留其他周期成功结果，且不得把失败显示为零。

#### Scenario: 部分失败

- **WHEN** 今日和本月成功而本周失败
- **THEN** 显示成功结果、本周错误及重试操作
- **AND** 单独重试本周不改变最近一次整体刷新时间

#### Scenario: 周期起点

- **WHEN** 服务查询今日、本周或本月
- **THEN** 起点分别为北京时间当天零点、周一零点或当月一日零点，终点为该次查询时刻

### Requirement: 身份与 Key 变更隔离

Host SHALL 限制 Client 可见数据为身份、掩码、状态和用量；秘密不得进入 Client 状态、日志、Session 或模型上下文。关闭、登出、切换用户或环境后，过期响应 SHALL NOT 更新当前界面。不同 Key 版本的数据 SHALL NOT 同时显示为同一结果。

#### Scenario: 查询期间 Key 轮换

- **WHEN** Key 状态和用量响应的版本不一致
- **THEN** 清除不一致结果并提示刷新，不把旧掩码与新用量组合展示

#### Scenario: 用户切换后旧请求返回

- **WHEN** 用户切换后前一用户的请求完成
- **THEN** 界面不显示前一用户的数据
