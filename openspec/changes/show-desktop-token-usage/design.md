# 设计：Desktop 本人 token 用量

## 界面

沿用账户菜单的现有模型 Key 入口和弹窗，将登录后的菜单项统一命名为“用量统计”，不在菜单项显示 Key 状态；Key 准备中、失败或使用手工 Key 等状态继续在弹窗内显示，原有重试操作仍可使用。弹窗标题为“Token 用量”，显示当前登录用户名、标签为“Key”的服务端掩码、现有模型 Key 状态，以及“今日”“本周”“本月”三行总 token。用量以千位分隔显示，单位为 token；不显示输入输出细分和额度。掩码仅展示，不提供复制或明文查看。

打开弹窗时查询当前 Key 信息和三个周期；整体刷新重新查询全部信息，统计标题下显示本次整体刷新发起时的日期和时间，不标注时区。单周期重试不修改该时间。时间使用服务统计时区 Asia/Shanghai 格式化；示意值不得作为真实数据。三个周期各自显示加载、成功或失败状态，失败行提供重试，成功的其他行保持可见。无 Key、Key 不可查询、登录失效、权限或网络错误均显示可理解的状态，不能显示虚假的零值。

## 数据与权限

新增 `GET /admin-api/dsh/llm-key/client/status` 与 `GET /admin-api/dsh/llm-key/client/usage?period=today|week|month`。两者只要求有效 Aicode OAuth2 登录，服务端从认证上下文确定用户，不接受目标用户或 Key ID。status 返回当前 Key 状态、`maskedKey`、`usageAvailable` 和可用于关联用量响应的 `keyVersion`；usage 复用现有 `queryUsage` 及其 `from`、`to`、`keyVersion` 和 token 计数。身份失效拒绝请求；不可查询的 Key 返回明确状态或错误。既有 `/mine`、`/mine/usage` 及管理员接口权限保持原样。

服务端沿用 Asia/Shanghai 自然日零点、周一零点和月初至查询时刻的统计，范围为 `[from, to)`，只统计当前 Key，沿用 TokenHub 总量，不将输入输出相加推算。每个请求独立实时查询，不持久化用量。status 的版本标识须与 usage 的 `keyVersion` 使用相同生成规则，不暴露明文或敏感标识。

Host 使用现有内存中的 Aicode OAuth2 Token 发请求，Client 只收到用户名、掩码、状态和统计数据。完整 Key、OAuth2 Token 与 TokenHub 管理凭据不得进入 Client 状态、日志、Session 或模型上下文。手工 Key 与自动 Key 在界面不加来源标签；用量和掩码均代表 aicode 返回的当前 Key，不能从本地手工 Key 推断其用量。

## 并发与一致性

每次打开或整体刷新创建新的查询代次；关闭、登出、切换用户或环境时废弃旧代次，延迟响应不得覆盖当前界面。单周期重试只替换该周期且不得覆盖更新的请求。状态响应和三个用量响应的 `keyVersion` 必须一致才能同时展示；若 Key 在查询期间轮换，清除不一致的数据并提示刷新，不将不同 Key 的掩码与统计拼在一起。整体刷新期间不得把旧数据标为本次新结果。

## 方案取舍与发布

新增 Desktop 本人接口使登录用户可查看自己的信息，同时保留既有管理接口权限；放宽 `/mine` 系列权限会改变其他调用方的授权规则，因此不采用。先部署兼容的 aicode API，再发布包含插件更新的 Desktop；旧服务缺少接口时客户端显示可恢复的不可用提示，不能假报零用量。用户不需手工迁移数据。
