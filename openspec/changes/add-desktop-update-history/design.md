# 设计：Desktop 更新发现与版本历史

## Context

Desktop 主菜单已有“关于”入口；该入口当前显示产品名称和 `app.getVersion()`。macOS 使用 Electron 系统 About panel，Windows 使用自定义消息框。更新菜单已有手动检查入口，私有更新机制定义启动调度和匿名 `POST /v1/desktop/updates/check` 请求。服务端当前响应包含可用更新与强制策略，但没有面向用户的发布说明历史。

## Goals / Non-Goals

**Goals:** 在“关于”区域显示当前版本和当前平台可用的发布历史；沿用已有私有更新请求报告版本；让用户在新版本提示后主动查看说明并决定是否继续更新。

**Non-Goals:** 系统状态栏常驻图标、单独的版本心跳接口、后管系统实现、变更记录编辑管理 UI、改造更新器差分/安装流程。

## Decisions

### 将“关于”作为版本与历史的统一入口

“关于”区域展示当前安装版本、当前平台历史记录列表及新版本可用提示。新版本可用时提示“有新版本可安装”，用户主动打开该版本详情后查看说明并进入现有下载/安装确认流程；发现更新不会自动下载或安装。手动检查继续使用现有更新菜单入口，成功发现更新时展示同一详情。

用一个 Desktop 自有的“关于”窗口承载版本、发布说明和更新操作。macOS 系统 About panel 只能展示固定元数据，无法呈现可浏览的历史列表和更新操作；Windows 当前消息框同样无法呈现列表。窗口由主进程持有版本和更新状态，渲染面只接收受限显示数据和显示/确认操作。不创建系统状态栏入口。

### 在现有检查响应中携带平台历史

扩展 `POST /v1/desktop/updates/check` 有效响应，携带适用于请求中 `platform` 和 `arch` 的发布历史列表。记录包含版本、目标平台和架构，以及中文和英文说明；更新详情复用同一记录。服务端按平台和架构筛选，客户端仍校验响应记录的目标平台与本机匹配后才展示。无历史记录时显示空状态，不影响当前版本显示或更新检查。

沿用现有检查接口避免客户端额外请求，也使检测版本统计、更新候选和其说明来自同一发布快照。此接口只读，不新增历史写入或管理端点。

响应示例：

```json
{
  "protocolVersion": 1,
  "release": { "version": "1.2.4", "feedUrl": "https://downloads.example/hxfl/stable/win-x64/" },
  "policy": { "minimumSupportedVersion": null, "forceAfter": null },
  "releaseHistory": [
    {
      "version": "1.2.4",
      "platform": "win32",
      "arch": "x64",
      "releaseNotes": { "zh_CN": "修复问题并改进稳定性。", "en_US": "Fixes and stability improvements." }
    }
  ]
}
```

### 启动检查失败不打扰用户

启动检查继续使用私有更新调度，提交已安装 Desktop 版本及可用的可选 `userId`。网络、服务端或协议失败时静默结束该次启动检查，不弹错误提示、不阻止启动；手动检查失败按现有手动更新错误交互展示。成功响应中没有新版本时不弹更新提示。启动检查发现新版本后显示非阻断提示；下载仍需用户打开详情并确认。

一次私有检查响应同时供更新候选、版本历史和强制策略使用，避免为了显示“关于”信息另发版本采集请求。现有更新器读取平台 feed 的 GET 请求仍照常进行。

## Risks / Trade-offs

- 把历史列表放入检查响应会增加响应体大小；首期只返回该平台的已发布版本记录及短发布说明，后续可在协议确有需要时引入分页。
- 发布历史和更新候选须来自一致的部署、通道、平台及架构筛选，避免向用户展示不可安装的版本。
- 该扩展要求后续管理后台同步实现响应字段；旧响应缺少历史字段时客户端可显示空历史，但仍按有效更新信息提示更新。

## Migration Plan

1. 为私有检查响应增加可选 `releaseHistory` 数组，不新增 endpoint。当前后管需实现的接口仍为 `POST /v1/desktop/updates/check`；feed、安装负载及 blockmap 资源沿用 `add-private-desktop-updates` 的清单。
2. 更新 Desktop 主进程的“关于”窗口和更新提示，兼容历史列表为空的情况。
3. 后管逐项补充 Windows x64 与 macOS arm64 发布版本和中英文更新说明；未提供历史字段的旧服务端仍可返回当前更新结果。
